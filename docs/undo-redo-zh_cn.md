# 撤销与重做 (undoRedo)

**中文** | [English](undo-redo.md)

`undoRedo` 为创造模式玩家提供服务端撤销与重做能力。

- 支持版本：`1.21.9+`
- 类型：`boolean`
- 默认值：`false`
- 分类：`feature`, `creative`

## 启用规则

```text
/carpet undoRedo true
```

规则关闭时，Undo/Redo 命令和客户端快捷键不会实际执行撤销或重做。

## 命令

```text
/undo
/redo
```

`/undo` 撤销当前玩家最近一次可撤销操作，`/redo` 恢复最近一次被撤销的操作。

该功能仅允许创造模式玩家使用。生存模式及其他非创造模式玩家无法执行撤销或重做。

## 客户端快捷键

DDS 客户端不是必须安装的。只安装服务端模组时，仍可完整使用 `/undo` 和 `/redo`。

客户端和服务端都安装兼容版本 DDS，并启用 `ddsNetworkProtocol` 时，可以使用：

```text
Ctrl+Z       撤销
Ctrl+Alt+Z   重做
```

快捷键只是命令操作的客户端入口，最终是否允许执行仍由服务端的 `undoRedo` 规则和玩家游戏模式决定。

## 记录范围

Undo/Redo 会跟踪一次玩家操作直接产生的世界变化，以及能够归属于该操作的后续延迟结果，包括：

- 方块状态变化；
- 方块实体及其数据变化；
- 实体生成、移除和相关状态变化；
- 容器与玩家背包之间的物品操作；
- Scheduled Tick 与 Block Event 等延迟工作；
- 红石延迟链；
- 幽匿感测体振动传播；
- TNT 等由上述链路继续触发的后续结果。

例如，已经验证的链路包括：

```text
感测体 A
→ 感测体 B
→ 中继器
→ TNT
→ /undo
→ /redo
→ TNT 再次被激活
→ /undo
```

Redo 恢复后重新产生的延迟红石和振动传播仍会继续归属于原操作，因此可以再次 Undo。

## 冲突保护

在执行 Undo 或 Redo 前，会检查相关世界状态是否已经被后续操作修改。

如果某一部分已经发生无法安全覆盖的冲突，该部分不会被强行恢复，从而避免旧历史记录覆盖其他后续修改。

自然运动、正常倒计时等属于同一操作后续生命周期的变化，会尽量与真正的玩家冲突区分处理。

## 历史记录

Undo/Redo 历史保存在服务器运行时内存中，不写入世界存档。

每名玩家的历史记录有内存上限；旧记录会在达到上限时自动淘汰。
